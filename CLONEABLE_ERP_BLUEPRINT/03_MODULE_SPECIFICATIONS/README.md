# Module Specifications

This section contains one independently implementable specification per discovered manifest-backed module.

## Standard artifacts

Each module directory contains:

- `README.md` — purpose, scope, evidence-backed artifacts, roles/security, data, APIs, UI, workflows, jobs, integrations, errors, tests, dependencies, extension points, and implementation requirements.
- `IMPLEMENTATION_CHECKLIST.md` — build, verification, acceptance, and unresolved-evidence checklist.

## Classification

Modules are organized under the source-derived blueprint categories in the Phase 1 coverage map. Category placement is an organizational view; the original source domain and module identity remain authoritative.

## Evidence boundary

The generated specifications establish implementation baselines from static evidence. They do not claim a module is installed, enabled, runtime-tested, or production-ready. Exact effective permissions, resolved view inheritance, deployed schemas, payload contracts, and external provider behavior require verification.
